# にいみコミュニティ メンバーズ

コミュニティ会員限定のWeb会員サイト（MVP実装）。

管理者が発行したログインID・パスワードを持つ会員のみが、限定公開動画・ブログ記事・お得な情報・お知らせ・イベント情報・ダウンロード資料を閲覧できます。

> ⚠️ **重要: このプロジェクトを開発したサンドボックス環境について**
> このコードは、外部ネットワークアクセスが制限されたサンドボックス環境で作成されました。
> Prismaのエンジンバイナリのダウンロード元（`binaries.prisma.sh`）にアクセスできなかったため、
> **`npx prisma generate` / `db push` / `migrate` / `seed` の実行、および `npm run build` の動作確認はこの環境内では行えていません。**
> コードはPrisma/Next.js/Auth.jsの標準的な作法に沿って記述しており、`npx tsc --noEmit` でチェックした結果、
> 検出されたエラーはすべて「Prisma Clientが未生成のため型がanyになる」ことに起因するもの（44件、原因は1種類）のみで、
> それ以外のロジックエラーは検出されていません。ロジック層（権限判定・ブルートフォース制御・特典期限判定・YouTube URL解析）は
> Prismaに依存しない単体テスト26件を作成し、**全て実行・成功を確認済み**です（`npm test`）。
> お手元の環境（インターネット接続可能な環境）で `npm install` を実行すれば、`postinstall` で自動的に `prisma generate` が走り、
> 上記の型エラーは解消されます。念のため、初回セットアップ後は `npm run build` で最終確認してください。

## 1. サービス概要

- サービス名（仮）: **にいみコミュニティ メンバーズ**（管理画面のサイト設定からいつでも変更可能）
- 会員限定のコンテンツ配信サイト。一般公開ページは存在せず、ログインした会員のみが利用できます。
- モバイルファースト設計（下部ナビゲーション、カード型UI）。

## 2. 主な機能（MVPスコープ）

- ログイン / ログアウト / パスワード変更 / パスワード再設定（開発環境は画面表示、本番はメール送信への差し替えが必要）
- ブルートフォース対策（5回失敗で15分ロック）、無効会員のログイン拒否
- 会員トップ（挨拶、重要なお知らせ、新着コンテンツ、メニュー）
- 動画一覧・詳細（YouTube埋め込み、カテゴリー絞り込み、キーワード検索、関連/おすすめ動画、お気に入り、視聴履歴）
- 記事一覧・詳細（リッチ本文のサニタイズ表示、お気に入り、閲覧履歴）
- お得な情報・特典（期限切れ自動判定）
- イベント情報（外部申込リンク対応）
- ダウンロード資料（ログイン必須・非公開ディレクトリ配信）
- お知らせ（重要度表示、既読/未読管理）
- マイページ（プロフィール編集、お気に入り、履歴）
- 管理画面（ダッシュボード、会員管理、動画/記事/お知らせ/特典/イベント管理）
- 会員種別（無料 / 通常 / プレミアム / 管理者）ごとの閲覧制御（**サーバー側で必ず判定**）

## 13. セキュリティ上の注意

- パスワードはbcryptでハッシュ化して保存。管理者を含め誰も平文パスワードを閲覧できません（再設定・仮パスワード発行のみ可能）
- 認証情報・シークレットはすべて環境変数で管理し、ソースコードに直書きしていません
- 権限判定（会員種別によるコンテンツ閲覧制限）は `src/lib/permissions.ts` の `canViewContent` を各Server Component / API Route / Server Actionで必ず呼び出し、**サーバー側で判定**します（クライアント側の表示制御のみに依存しません）
- ブルートフォース対策: 5回ログイン失敗で15分間ロック（`src/lib/login-guard.ts`）
- SQLインジェクション対策: Prisma使用によりSQL文を直接組み立てない
- XSS対策: 記事・お知らせ本文はDOMPurifyで保存時・表示時に二重サニタイズ
- CSRF対策: Auth.jsの標準機構、およびServer Actionsの同一オリジン制約を利用
- セッション固定攻撃対策: DBセッション方式を採用し、ログインの都度サーバー側でセッションを発行
- IDの直接指定による不正閲覧対策: 動画/記事/特典/イベント等の詳細ページは、都度サーバー側で「公開済みか」「削除されていないか」「会員種別が対象か」を検証し、該当しない場合は404を返します
- 未認証APIアクセス対策: ダウンロードAPI (`/api/materials/[id]/download`) はセッション検証・会員有効性検証・権限検証を行った上でのみファイルを返します
- ファイルアップロード対策: MVPではファイルアップロード機能は未実装（資料は開発者/管理者がサーバーに配置する運用）。将来UIから追加する場合は、拡張子・MIMEタイプ検証、ファイルサイズ制限、実行不可ディレクトリへの保存を必須にしてください

## 14. バックアップ方法

- **開発環境（SQLite）**: `prisma/dev.db` ファイルを定期的にコピーしてください
- **本番環境（PostgreSQL）**: `pg_dump` による定期バックアップを推奨します（例: `pg_dump $DATABASE_URL > backup_$(date +%Y%m%d).sql`）。マネージドDB（Vercel Postgres, Supabase, RDS等）を利用する場合は、サービス側の自動バックアップ機能を有効化してください
- ダウンロード資料ファイル（`storage/materials/`、または移行後のクラウドストレージ）も別途バックアップ対象に含めてください

## 15. よくあるエラーと解決方法

| 症状 | 原因 | 対処 |
|---|---|---|
| `prisma generate` が失敗する | ネットワーク制限でエンジンバイナリを取得できない | インターネット接続可能な環境で実行してください |
| ログインできない | パスワード誤り、またはロック中 | 5回失敗すると15分ロックされます。時間を置くか、管理者に仮パスワード発行を依頼してください |
| 会員が動画/記事を見られない | 会員種別の閲覧許可対象外 | 管理画面の対象会員種別設定を確認してください |
| 資料がダウンロードできない | 未ログイン、または対象会員種別外 | ログイン状態と会員種別を確認してください |
| 本番でダウンロード資料が消える | サーバーレス環境のファイルシステムは永続化されない | クラウドストレージへの移行が必要です（11章参照） |

## 16. データベース設計と設計判断の理由

主要モデル（`prisma/schema.prisma` に完全定義）:

`User, MemberProfile, MembershipPlanConfig, Session, Account, Video, VideoCategory, VideoView, VideoFavorite, Article, ArticleCategory, ArticleView, ArticleFavorite, Announcement, AnnouncementRead, Benefit, Event, DownloadMaterial, DownloadLog, AdminLog, SiteSetting`

### 個人情報・認証情報の扱いについて

- 会員登録時に取得する個人情報は **氏名・表示名・メールアドレスのみ** に限定しました（要件どおり、住所・電話番号は収集しません）。将来必要になった場合は `MemberProfile` に追加するか、専用テーブルを新設し、`User` 本体を肥大化させない設計にしています。
- パスワードは `passwordHash` カラムにbcryptハッシュのみを保存し、平文を保持するカラムは一切設けていません。
- 管理者専用メモ（`MemberProfile.adminNote`）は会員本人には非公開情報として `User` から分離しました。会員が自分のプロフィールを閲覧・編集するAPI/画面から絶対に参照しないことで、意図しない漏洩を防いでいます。
- `Session` / `Account` はAuth.js標準モデルをそのまま採用し、将来のGoogleログイン・LINEログイン追加時に相互運用できるようにしています。

### 削除方針

- 会員 (`User`)・動画・記事・お知らせ・特典・イベント・資料は、原則として `deletedAt` による**論理削除**を採用しました。誤操作からの復旧余地を残すためです。
- `Session` / `Account` / `VideoView` / `VideoFavorite` などの関連レコードは、親（User）が削除された場合に `onDelete: Cascade` で物理削除される設計です（認証・視聴ログという性質上、論理削除の必要性が薄いため）。
- `AdminLog`（管理ログ）は削除機能を設けていません。監査証跡として残す設計です。

### インデックス・ユニーク制約の考え方

- ログイン検索が最頻出の操作であるため、`User.email` と `User.loginId` にユニーク制約を設定しています。
- 動画・記事・お知らせ・特典・イベントは「公開状態 + 公開日/開始日でのソート」が一覧表示の基本クエリとなるため、複合インデックス（例: `[isPublished, publishedAt]`）を設定しています。
- 会員種別ごとの閲覧制御 (`allowedPlans`) は、SQLiteでも配列カラムを使わずに済むよう **カンマ区切り文字列** として保存し、アプリケーション層 (`src/lib/permissions.ts`) でパース・判定する設計にしました。本番のPostgreSQLでは配列型やジャンクションテーブルへの置き換えも可能ですが、MVP段階では実装コストと可搬性（SQLite/PostgreSQL両対応）を優先しました。

## 18. 管理者向け操作マニュアル（抜粋）

- **会員登録**: 管理画面「会員管理」→「新規会員登録」から氏名・メール・ログインIDなどを入力すると、システムが仮パスワードを自動発行します。発行された仮パスワードはその場でのみ表示されるため、確認後、安全な方法（対面・電話等）で会員へお伝えください。
- **会員停止/削除**: 会員編集画面から「一時停止」、または「削除（退会）」を実行できます。削除は確認画面を経由し、即時の完全削除ではなく退会扱い（論理削除）になります。
- **仮パスワードの再発行**: パスワードを忘れた会員がいる場合、会員編集画面の「仮パスワードを発行する」から新しい仮パスワードを発行できます。管理者は現在のパスワードを閲覧できません。
- **コンテンツの公開/非公開**: 動画・記事作成/編集画面の「公開する」チェックボックスで切り替えます。チェックを外すと会員画面から見えなくなります（削除ではありません）。
- **対象会員種別**: 各コンテンツの編集画面で「対象会員種別」を選択することで、無料会員には見せず、プレミアム会員限定にする、といった制御が可能です。

## 24. 会員数規模別の運用上の課題

| 会員数 | 課題 |
|---|---|
| 〜100人 | 現構成（Vercel Hobby + 小規模PostgreSQL）で問題なく運用可能。運用は手動で十分 |
| 〜500人 | DB接続数・クエリ性能の監視が必要になる。管理画面でのCSV一括登録・出力の実装が望ましい。YouTube限定公開URLの流出リスク管理をより厳格に（署名付きURL等への移行を検討） |
| 〜1,000人 | PostgreSQLのプラン増強、DB接続プーリング（PgBouncer等）の導入を検討。アクセス分析・人気コンテンツ集計のためのキャッシュ層（Redis等）導入を検討。問い合わせ対応の仕組み化（FAQ拡充、サポート体制）が必要 |

## 25. 有料会員化する場合の追加開発項目

- Stripe（または国内決済代行）との連携、サブスクリプション管理
- 決済失敗時の会員ステータス自動更新（`MemberStatus` を `EXPIRED` に自動遷移させるバッチ処理）
- 請求書・領収書発行
- プラン変更（アップグレード/ダウングレード）フローとUI
- 返金・解約フロー
- 会計・税務対応（インボイス制度対応等、要専門家確認）

## 26. セキュリティ面で特に注意すべきポイント

1. **YouTube限定公開の限界**: URLを知っていれば第三者が視聴できる可能性があるため、機密性の高い動画は署名付きURL配信サービスへの移行を検討してください（動画編集画面にも注意書きを表示済み）
2. **管理者アカウントの管理**: 管理者権限を持つアカウントは最小限に留め、定期的なパスワード変更を推奨します
3. **本番デプロイ前の初期パスワード変更**: シードデータのパスワードは開発用であり、本番投入前に必ず変更してください
4. **ファイルストレージの移行**: サーバーレス環境ではローカルファイルシステムが永続化されないため、本番運用前に必ずクラウドストレージへ移行してください
